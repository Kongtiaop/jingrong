diag(rag): 在独立临时表上定位可行的 BM25 索引定义

REINDEX 成功但写入仍失败 -> 问题不在索引元数据陈旧，而在**索引定义本身**。
当前定义: USING bm25 (content) WITH (key_field=id)
  字段列表只有 content，key_field 仅在 WITH 中声明；
  0.2x 之后文档多写作 (id, content) + WITH (key_field='id')。

本脚本在**独立临时表** probe_bm25_var 上对照 4 种候选定义
（A 含 key_field 字段 / B 仅 content+WITH = 现状 / C 含 key_field 无 WITH / D 仅 content），
逐个建索引+插入+删索引，找出哪种能写入，用完即 DROP TABLE。

安全修正：上一版设计为在 knowledge_chunk 上"事务内 DROP 旧索引 -> 建候选 -> 探测 ->
ROLLBACK"。但 PG DDL 若回滚未按预期生效，原索引会真的消失、检索当场失效——
用会破坏现有能力的实验去诊断问题，风险不可接受。故改为临时表，不触碰生产表。
并在结论中说明局限：临时表仅两列，若失败与 vector 列等其它因素相关则不覆盖。
