## C. 10 段伪代码速记卡

### 1. 自然语言下单 ◆ 最能打
```
draft: 解析(产品/金额) → 缺参澄清(绝不猜) → 产品/余额/适当性校验 → 一次性令牌(DB存哈希)
confirm: FOR UPDATE锁行 → 幂等短路(order_id已存在) → 令牌校验 → 重跑校验防TOCTOU → 幂等建单
```
追问：为什么重跑校验？→ TOCTOU。为什么存哈希？→ 泄库拿不到+常量时间比。

### 2. 交易状态机+幂等 ◆ 唯一索引是"只成功一次"
```
transition: 非法迁移抛错 + 写 order_status_history
幂等: 预查命中返回旧单; 并发双写撞唯一索引→409
```
追问：并发都miss？→ 唯一索引兜底。为什么不用Redis？→ 无持久化。

### 3. RBAC+SubjectScope ◆ SQL参数服务端改写
```
操作级: requirePermission(权限码)
数据级: authorizedSubjectIds(授权表) → SQL的subject参数改写为授权闭包
```
追问：为什么不信前端id？→ 服务端改写，客户传什么id都绕不过。

### 4. 权限版本化缓存 ◆ 版本号→指纹→旧key失效
```
key=wm:{ns}:pc-{指纹}:sc-{范围}; 版本号进指纹
角色变更→INCR版本号→指纹变→旧key靠TTL回收
```
追问：为什么版本号不删key？→ O(1)/原子/精确；指纹是安全底线，授权永不依赖缓存。

### 5. RAG混合检索+RRF ◆ 分数语义≠相似度
```
文本腿(ts_rank_cd)+向量腿(cosine)→RRF(1/(60+rank))融合→top_k
min_score=0.0001滤0分项; 真正拒答=无有效引用→转人工
```
追问：min_score这么低？→ RRF融合分量级0.01-0.03；局限=拦不住"召回了不相关"，需阈值/Reranker。

### 6. 受控NL2SQL ◆ 模型只填参数不拼SQL
```
入口拒SQL→模板白名单(approved+角色+只读)→参数契约→目录引用范围→外层LIMIT+绑定参数→失败rollback
```
追问：为什么不直接生成SQL？→ 无法保证只读/防注入/口径统一；nl2sql_ready=False。

### 7. 多Agent编排 ◆ 确定性优先LLM只兜底
```
Supervisor→意图规划→路由→DAG并行(max4)→汇总→审计
澄清2次转人工; ReAct上限20+结果哈希早停; LLM回退默认关
```
追问：LangGraph怎么用？→ 真图已实现可运行：只读知识意图走 LangGraph **ReAct 条件循环**（react_step→结果哈希早停→回环→react_done→**generate_node LLM生成答案**），交易/风控等高安全走**确定性 execute 节点**；生产默认仍走确定性管线，二者共享handler。这就是"软AI硬底座"落到编排：模型只管只读推理，高风险不动。

### 8. Outbox+Worker ◆ 业务与事件同事务
```
业务+outbox_event同commit → outbox_worker(FOR UPDATE SKIP_LOCKED)→Redis Stream→幂等消费+死信
```
追问：为什么不直接同步？→ 慢调用拖垮主链路；同事务不丢、Streams持久化+幂等。

### 9. 记忆 ◆ 业务事实表永远高于记忆
```
短期(Redis 30min)管会话连续; 长期(PG CustomerMemory)管跨会话事实+事件审计
P3乐观锁: 读版本→if_version条件写→冲突合并重试(对齐Opus5)
```
追问：记忆会覆盖事实吗？→ 不会，业务表优先。为什么记忆是数据不是指令？→ 防污染。

### 10. 渐进式披露RAG ◆ 先目录按需打开
```
分库预筛→metadata目录(不读正文)→结构感知(读大纲)→精确读取(直读片段+溯源)
短文档/无结构→跳过结构感知直接读
```
追问：和普通RAG区别？→ 不靠向量撞chunk，按结构定位直读。和Opus5？→ 同一套，方向不同。

## D. 关键数字/事实（记牢）

- **50 张表**，PostgreSQL+pgvector 唯一业务事实源。
- **评测三率口径**（`run_intent_eval.py`）：**意图匹配率**=期望意图 ⊆ 实际意图（子集，多识别不算错）；**澄清匹配率**=模型 `requires_clarification` 布尔是否与期望一致（金融"该问不问会带错下单"）；**完全准确率**=意图对**且**澄清对。故意图 95.3% 但完全仅 81.2%（差的就是"意图对、澄清判断分歧"那批）。
- 幂等唯一索引：orders / notification / async_task 的 idempotency_key + nl_draft 令牌哈希。
- 金额 `Numeric(18,2)`；份额 `Numeric(18,4)`；禁 float。
- 状态机：`pending_confirmation→pending_review→executing→executed`（+cancelled/rejected）。
- 确认令牌 15 分钟、一次性、只存 SHA-256、常量时间比较。
- ReAct 上限 20 + **结果哈希早停**（每轮 hash 工具结果，重复即停）；澄清上限 2 次；`max_parallel_tasks=4`。
- RRF k=60；min_score=0.0001；top_k=5；embedding 1024 维（Qwen）。
- Outbox `FOR UPDATE SKIP_LOCKED`；XCLAIM 30s；死信 attempt≥3。
- **压测（本地单节点）**：0 错误；优化后（4 worker+health缓存+asset快照复用）混合100并发 RPS 151→625、P50 606→98ms；health 200 并发 RPS 421→1052；profile/me 50 并发 RPS 95→406、P50 457→46ms；50k 数据查询不退化。优化杠杆=多worker+减每请求DB往返+health缓存。

## E. 诚实边界（背下来防戳穿）

1. 项目是 **MVP/原型**，不是上线兜真钱的系统。
2. **有本地性能基准、无生产级压测**（`docs/性能压测报告_2026-08-28.md`：并发 0 错误、50k 查询不退化、P95 数据）——被问生产 QPS 说"未做生产级多节点压测"，别编。
3. LangGraph 真图已实现可运行 + **Checkpointer 断点续跑已接入**（MemorySaver 测试过、AsyncPostgresSaver 需装额外包）；但**生产默认仍走确定性管线**（二者共享 handler）。
4. 长期记忆链路**未接**（P3 计划）。
5. `nl2sql_ready=False`（自由 SQL 关闭）；Milvus/Neo4j 是 P5 可选。
6. CI/CD、生产部署、备份是上线前待补（P0）。

## F. 高频追问接法（一句话）

| 追问 | 接法 |
|---|---|
| 简历 React？ | 前端 Vue3；表述统一，必要时说项目前后端有 Vue/React 两种情况，代码以 Vue 为准 |

| 为什么全并行不行？ | 可并行的是只读分析，资金/订单/风控结论不可逆，必须确定性+人工 |
| 飞轮要微调吗？ | 不改代码不改模型，只改运行时配置，改完立即生效错了回滚 |
