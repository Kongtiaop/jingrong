# 可配置理解层 + 难度模型路由设计

> 版本：v1.0　日期：2026-08-28
> 核心：**理解层可配置、可模型自调（飞轮的意义）；执行层固定轨道、模型不可改（安全底线）。**
> 关联：`数据飞轮与意图识别评测.md`、`Agent & RAG 数据飞轮：从规划到落地.md`、Harness 叙事。

---

## 1. 一句话架构

> **模型负责理解，规则负责执行。理解层的所有旋钮（提示词、few-shot、top_k、知识文档、意图映射、甚至难度模型路由）都做成运行时配置、可被模型自调；执行层的闸门（权限/风控/确认/幂等/审计/写操作）锁死在固定轨道，任何配置/模型都改不了。**

```
理解层（可配置、模型可自调）
  提示词 / few-shot / 意图映射 / 工具schema / 检索参数(top_k) / 知识文档范围 / 难度模型路由
        ↓ 模型自调（auto-repair 改配置，人门控+灰度+回滚）
执行层（固定轨道、模型不可改）
  权限 / SubjectScope / 适当性 / 风控 / 确认令牌 / 幂等 / 审计 / 写操作
```

---

## 2. 理解层可配置项（飞轮的旋钮）

| 配置项 | 示例 | 影响 | 模型能否自调 |
|---|---|---|---|
| **系统提示词** | 意图解析 prompt | 该 Agent 所有推理 | ✅ |
| **few-shot 示例** | 多意图/否定示例 | 对齐意图体系 | ✅ |
| **意图映射** | `INTENT_ALIASES`/`INTENT_KEYWORDS`/`INTENT_TO_TEMPLATE` | 模型输出→规范码 | ✅ |
| **工具 Schema** | `INTENT_TOOL_SCHEMA` | 结构化输出约束 | ✅ |
| **检索参数** | `top_k`、RRF k、相似度阈值 | RAG 召回 | ✅ |
| **知识文档范围** | 某意图检索哪个库/分类 | 召回命中 | ✅ |
| **难度模型路由** | 简单→小模型，复杂→大模型 | 成本/质量 | ✅ |

> 这些就是飞轮"落地（改配置）"要动的对象——全部运行时读取，**改配置即生效，不需改代码/部署**。

---

## 3. 难度模型路由（按问题难易选模型）

### 3.1 为什么
不是所有请求都要最强模型。简单意图（订单查询、转人工）用小模型（快、省、稳）；复杂/多意图/模糊用大模型（准）。这就是"该硬的地方用对的模型"，也是成本与质量平衡。

### 3.2 难度分级
| 难度 | 判定 | 模型（示例） |
|---|---|---|
| **S（简单）** | 规则置信度高、单意图、明确 | `qwen-turbo`（对应百灵 Ling-tiny） |
| **M（中等）** | 多意图、需检索、略模糊 | `qwen-plus`（对应百灵 Ling-flash） |
| **L（复杂）** | 否定/指代/歧义/对抗/长句 | `qwen-max`（对应百灵 Ring 旗舰） |

> **模型口径**：以 **Qwen 系为主**，括号内为对应的**蚂蚁百灵商用模型**（百灵需额外付费，仅作为选型/简历口径；实际代码接 Qwen/DashScope，可按部署切换供应商）。对应关系：`qwen-turbo↔Ling-tiny`、`qwen-plus↔Ling-flash`、`qwen-max↔Ring`。

### 3.3 判定信号（可配置权重）
- 规则置信度（`_patterns` 的 confidence）
- 意图数量（单/多意图）
- 是否含否定/歧义/连词（正则标记）
- 是否有缺参需澄清

### 3.4 路由配置（外部化）
```yaml
model_routing:
  default: qwen-plus
  tiers:
    - {max: "S", model: "qwen-turbo"}   # 百灵 Ling-tiny
    - {max: "M", model: "qwen-plus"}    # 百灵 Ling-flash
    - {max: "L", model: "qwen-max"}     # 百灵 Ring 旗舰
```

## 4. 配置存储与运行时加载

- **存储**：`config/understanding.yaml`（或 DB），含提示词/few-shot/意图映射/检索参数/模型路由。
- **运行时加载**：应用启动读入内存 + 支持热刷新（改配置后 reload）。
- **版本化 + 可回滚**：每次变更记录 version + 变更前快照，可一键回滚。
- **不重新部署**：改配置即生效。

---

## 5. 模型自改路径（飞轮全自动）

```
评测集 → 失败案例 → auto_repair 生成修复候选(Diff) → 写入 config/understanding.yaml
       → 校验(结构/白名单/不越界) → 人工门控 → 灰度 → 回滚 → 重跑评测
```

- **校验**：模型写的配置必须过 schema 校验 + 白名单（不能引入非法值/越界）。
- **门控**：关键变更（模型路由、提示词大改）需人工审批；小变更（关键词增补）可自动。
- **灰度 + 回滚**：先小流量，异常即回滚（复用权限缓存/配置版本机制）。

---

## 6. 安全边界（固定轨道，模型不可改）

| 执行层闸门 | 为什么模型不可改 |
|---|---|
| 权限 / RBAC / SubjectScope | 模型改了就=越权 |
| 适当性 / 风控 / 确认令牌 / 幂等 | 模型改了就=绕过合规 |
| 审计 / 日志 | 模型改了就=掩盖 |
| 写操作 / 资金 / 订单 | 模型改了就=直接动钱 |
| `ILLEGAL_MUTATION` / 交易永不升级 / `must_not_submit` | 模型改了就=削弱防注入/防越权 |

**实现保障**：执行层闸门**硬编码在代码里，且不在模型可写的配置域内**。配置系统只开放理解层域，执行层配置不可被 auto-repair 写入（写白名单限制）。

---

## 7. 落地顺序

| 阶段 | 内容 |
|---|---|
| **P0** | 外部化"理解层"配置（提示词/few-shot/意图映射/检索参数）+ 运行时加载 |
| **P1** | 难度模型路由（S/M/L → 模型），接入意图解析 + RAG 生成 |
| **P2** | auto-repair 直接写配置 + 校验 + 门控 + 灰度 + 回滚（模型自调闭环）|
| **P3** | 知识文档范围动态化（某意图可配检索库/分类）|

---

## 8. 一句话收尾

> "我的系统是**理解层开放、执行层封闭**——模型可以自调提示词、top_k、甚至按难度换模型（这是飞轮的价值），但权限、风控、确认、幂等、审计这些'该硬的地方'永远锁死在固定轨道。**模型能优化自己怎么理解，但永远改不了自己能不能执行。**"
