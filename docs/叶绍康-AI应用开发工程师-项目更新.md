## 项目背景（痛点）

金融财富管理行业的 AI 中台，面向投顾、客服、风控、运营、客户经理五类角色。核心痛点：
- **人工成本高、服务无法规模化**：投顾一对一服务，客户量大时顾不过来；
- **知识沉淀难 / 查不到**：2000+ 份制度、政策、产品说明书散落，关键词搜不到语义；
- **风险与合规不可控**：模型自由决策易越权、易用过期政策当依据、易编造；
- **客户信息在服务链条上断裂**：客服记的偏好，投顾看不到；风控预警，客服不知道。

系统目标：让 AI 只做"理解、推荐、解释、辅助决策"，**权限、风控、适当性、确认、执行永远由确定性业务系统负责**，把 AI 限制在可解释、可验证、可审计的辅助范围内。

LangChain / LangGraph、FastAPI、SQLAlchemy Async、PostgreSQL+pgvector、Redis Streams + Outbox、Qwen（DashScope）、Vue 3、Docker Compose、GitHub Actions CI/CD、Pytest / Playwright

## 核心职责（每条 = 业务痛点 → 技术方案 → 亮点）

### 1. 多 Agent 编排与安全边界
**痛点**：单一 Chatbot 职责混乱，模型易越权访问客户数据或直接执行高风险操作。
**方案**：Supervisor 统一编排 + 5 类专业 Agent（客服/投顾/风控/数据分析/业务操作）；AgentCapabilityRegistry 做**能力白名单前置过滤**，按用户类型、角色权限、授权客户范围（Subject Scope）限制 Agent 与工具调用；基于 LangGraph 实现状态机、条件分支、最大迭代/工具预算与异常兜底，受控 ReAct 只读、高风险走受控工作流。
**亮点**：模型无法通过文本提交任意 customer_id，查询与工具调用由后端再校验；越权用例阻断，AI 不绕过适当性与订单状态机。

### 2. 金融业务闭环（AI 辅助但不越权）
**痛点**：用户想"自然语言下单"，但 AI 不能直接成交、不能绕过风控与确认。
**方案**：实现「自然语言申购 → 订单草稿 → 产品/适当性/风险/范围预检 → 用户显式确认令牌 → 幂等建单」链路；确认令牌仅活在单次草稿响应、不持久化，服务端校验有效性，重复确认返回同一订单。
**亮点**：AI 只生成持久化草稿，不冻结资金、不直接成交；键幂等 + 令牌防重，正确阻止重复建单与越权执行。

### 3. RAG：职责分离 + 引用溯源 + 增量更新
**痛点**：把过期政策当事实、答案无依据、政策小改全量重算。
**方案**：职责分离——RAG 只负责解释层（公司信息/流程/FAQ），"订单/余额/持仓"等业务事实直接查 PostgreSQL，冲突以业务表为准；多格式文档解析（MinerU）+ 父子块语义分块 + dense/BM25 混合检索 + Reranker 精排 + 引用溯源；两级哈希（file_hash/chunk_hash）做增量更新，历史版本独立保留，只检索"当前生效"版本。
**亮点**：修改一个条款仅 [N] 个片段需重新向量化，更新从 [30分钟]→[2分钟]；引用标注来源文档/页码，零合规事故。

### 4. 分层共享记忆（L0–L3）
**痛点**：客户信息在服务链条上断裂——客服记的偏好投顾看不到，记忆相互孤岛。
**方案**：构建四层记忆——L0 原始会话流水、L1 结构化事实卡片、L2 场景档案（跨 Agent 共享）、L3 长期画像；用 **private/shared/organization 三种作用域**控制多 Agent 共享边界，记忆带来源、置信度、有效期、事件审计；权威业务事实（余额/持仓/风险/交易状态）始终从业务表读，**记忆不推断、不覆盖、不替代**。
**亮点**：客服记录的"偏好稳健型"，三天后投顾推荐能直接检索到；风控凌晨预警，早上客服能看到风险上下文主动提醒——记得住、可共享、可沉淀、可审计。

### 5. 记忆驱动推荐（从"存"到"用"）
**痛点**：记忆只存不用，推荐仍是"一刀切"。
**方案**：长时记忆记录客户风险/产品/投资期限偏好，推荐时做**软排序**（只调顺序、绝不突破适当性硬门禁）；支持**产品指代消解**（"这个/那个产品"结合当前对话）与**裸产品名句识别**，多轮对话能接住上下文。
**亮点**：客户表达偏好后，后续推荐自动匹配其风险/期限偏好顺序，提升推荐命中与转化；同时守住适当性底线。

### 6. 数据飞轮与质量闭环
**痛点**：模型回答不准，靠人工发现，难以持续改进。
**方案**：构建 **bad case 数据飞轮**——线上自动采集（意图未知/低置信/证据不足/转人工）→ 去重落库 → **标注界面**人工标注正确意图 → 导出黄金评测集 → LLM 生成修复候选 → 调优集自动验证（只落地提升/非降批次）→ 版本化快照 + 一键回滚 → 灰度放量（按查询哈希分流）。
**亮点**：意图识别完全准确率从 [60%]→[80%+]；评测集持续扩充、可回滚、可灰度，模型"越用越准"而非越堆越乱。

### 7. L3 会话摘要 + 多轮综合回答
**痛点**：模型记不住历史，多轮对话总"失忆"。
**方案**：对话中由 **memory_worker 异步提炼**会话摘要（转人工/多轮会话触发），落共享记忆；通过 **L3 摘要 + 记忆召回**喂回**意图分类**与**回答生成**上下文，模型多轮后能结合客户历史关注点作答。
**亮点**：实现"先存后用、可召回"的记忆管线，情景记忆真正参与回答，而非只存不用。

### 8. NL2SQL：目录约束型受控分析
**痛点**：非技术人员取数难，自由 SQL 有越权/注入/口径风险。
**方案**：摒弃自由 SQL 生成，采用"数据目录召回 + 已批准只读模板 + 表字段双白名单 + 参数安全契约 + 授权范围绑定"，独立 nl2sql_policy 策略层；自然语言提问 → 只读聚合结果 → 图表渲染。
**亮点**：取数从排期 [2天]→[30秒]出图；从源头杜绝"删库跑路"和越权查敏感数据。

### 9. 异步工程化 + 真实上线 + CI/CD
**痛点**：耗时/外部模型调用拖慢同步接口，交付不可重复。
**方案**：Redis Streams + Outbox + Worker 承接通知、知识导入、目录向量化、客服超时、AML 日扫、记忆摘要等异步任务，重试/死信/人工重放；**GitHub Actions CI/CD**（pytest + 前端构建 + SSH 自动部署），已**前后端分离部署**（nginx + FastAPI + 8 个 Worker）到阿里云真实访问；180+ 单测 + 记忆管线 E2E。
**亮点**：从开发到上线可一键、可回滚、可重复；主链路真实可访问。

## 个人优势（保留/微调）

以解决实际问题为驱动，不炫技不堆砌，追求投入产出比——能用轻量模型解决的不用大模型，能用规则兜底的不用模型硬猜。在金融合规场景积累：知道何时该让 AI 出草稿等人确认、何时用监督/规则实时拦截、何时把控制权交还业务系统。对 LLM 底层原理与前沿架构保持持续学习，坚持动手验证。
