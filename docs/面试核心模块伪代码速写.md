## 1. 自然语言下单闭环（草稿→确认→幂等）◆ 最能打的一段

> 核心：AI 只出草稿，确认令牌 + 幂等才建单，确认时重跑校验防 TOCTOU。

```text
func createDraft(customerId, text):
    parsed = parseIntent(text)                 # 引号产品名 + 金额(万/元, Decimal)
    if 缺产品 or 缺金额: return needsClarification(missing_fields)   # 绝不猜测
    if 非申购(赎回/卖出): return needsClarification("MVP仅支持申购")
    product = 匹配active产品(去空格精确匹配)
    if 无/多匹配: return needsClarification(product_options≤5)
    if not 适当性校验(product, customer): return precheckFailed(原因)
    if 账户余额 < 金额: return precheckFailed
    # 生成一次性确认令牌，DB只存哈希
    token = secrets.token_urlsafe(32)
    draft = 存(产品, 金额, token_hash=sha256(token), expires_at=now+15min,
               input_fingerprint=sha256(customer|product|amount|version))
    return draft_id, token, expires_at          # 明文token只返回这一次

func confirmDraft(draftId, customerId, token, idempotencyKey):
    lock row (SELECT ... FOR UPDATE)            # 防并发双击
    if draft.order_id 已存在: return 该订单       # 幂等短路
    if draft.status != awaiting: error
    if draft.expires < now: 置expired; error
    if !constantTimeEq(sha256(token), draft.token_hash): error(403)
    # TOCTOU：确认时重跑全部确定性校验
    重查产品active / 账户 / 余额 / 适当性
    key = idempotencyKey or f"nl-draft:{draft.id}:v{draft.version}"
    order = createOrder(产品, 金额, idempotency_key=key)   # 内部唯一索引兜底
    回写 draft.order_id; status=confirmed
    audit("confirm_draft"); return order
```

**追问点**：为什么确认时重跑校验？→ 防 TOCTOU（草稿与确认之间产品/余额/适当性可能变了）。为什么 DB 只存哈希？→ 泄库也拿不到可用令牌；常量时间比较防时序攻击。

## 2. 交易状态机 + 幂等 ◆ 唯一索引是"只成功一次"的保证

```text
# 状态机唯一权威
func transition(order, to):
    if to not in ALLOWED[order.status]: throw TradingError   # 非法迁移
    append order_status_history(from, to, operator, note)    # 可追溯
    order.status = to

ALLOWED = {
  pending_confirmation: {pending_review, cancelled},
  pending_review:       {executing, rejected, cancelled},
  executing:            {executed},
  executed/rejected/cancelled: {}                            # 终态
}

# 幂等：预查是优化，唯一索引才是保证
func createOrder(...):
    if idempotency_key and 已存在(user_id, key): return 该订单   # 命中返回旧单
    insert order                        # 撞唯一索引 ux(user_id,idempotency_key)
    # 并发双写：后插入者抛 IntegrityError → 映射 409 IDEMPOTENCY_CONFLICT
```

**追问点**：并发两个请求都 miss 预查怎么办？→ 唯一部分索引兜底，后插入者报冲突，客户端重试命中旧单。为什么不用 Redis？→ Redis 无持久化、不可靠，金融用 DB 唯一索引更稳。

## 3. RBAC + SubjectScope 防越权 ◆ SQL 参数服务端改写为授权闭包

```text
# 操作级：权限码注入
func requirePermission(user, code):
    if user.is_super_admin: pass
    perms = {p.code for role in user.roles for p in role.permissions}
    if code not in perms: 403

# 数据级：能看哪些客户
func authorizedSubjectIds(user):
    if user.is_super_admin: return set()        # 空=无限制
    return SELECT customer_id FROM customer_advisor_authorization
           WHERE advisor_id=user.id AND status=active AND 有效期 AND NOT revoked

# 关键：把SQL的subject参数改写成授权闭包
func bindSqlParams(userQuery, template):
    scope = authorizedSubjectIds(user)
    subjectParam = scope or currentUserId        # 服务端改写，不是前端传参
    if userQuery 里出现 不在scope的客户id: 拒绝 unauthorized_subject
    return template.withParams(subject=subjectParam)   # 客户传什么id都绕不过
```

**追问点**：为什么不信任前端传的 customer_id？→ 前端可被绕过；参数在服务端改写为授权闭包，最终执行的查询参数是服务端算的。

## 4. 权限版本化缓存 ◆ 版本号变了→指纹变→旧key逻辑不可达

```text
# key = wm:{ns}:pc-{指纹}:sc-{范围指纹}
fingerprint = sha256(规范化JSON(role_codes, permission_codes, data_scope_version))[:24]

func get(key, user):

    cacheKey = buildKey(context, scope)
    if cache.get(cacheKey): return 缓存            # 命中
    return 实时计算()                              # 未命中走真实查询

func 角色变更(user):
    INCR wm:permission-context-version:{user_id}   # 版本+1→指纹变→旧key逻辑失效靠TTL回收
    # 不删key：O(1)、原子、粒度精确；即使INCR失败指纹仍含实时权限码=安全底线
```

**追问点**：为什么用版本号不直接删 key？→ 不需要枚举/SCAN Redis、O(1)、原子无竞态；双保险（版本号急切失效 + 指纹安全底线）。Redis 挂了安全吗？→ 缓存失败返回 None 走实时查询，授权永不依赖缓存。

## 5. RAG 混合检索 + RRF + 置信度转人工 ◆ 分数语义与拒答条件

```text
func searchHybrid(query, embedding, topK, scope):
    candK = max(topK*4, 20)
    textRows  = 全文检索 to_tsvector+ts_rank_cd, limit candK   # 文本腿
    vecRows   = embedding? cosine_distance, limit candK        # 向量腿
    # RRF融合：只用排名，不用跨通道分数
    for chunk in union(textRows, vecRows):
        rrf = 0
        if chunk in textRows: rrf += 1/(60 + textRank[chunk])
        if chunk in vecRows:  rrf += 1/(60 + vecRank[chunk])
    return sortBy(rrf).top(topK)

func answer(query, intent):
    if greeting: return greeting
    embeddings = tryEmbed(query) or fallback(text检索, evidence=embedding_degraded)
    citations = searchHybrid(query, embeddings, topK=5, scope=scope)
    useful = [c for c in citations if c.score >= min_score]   # min_score=0.0001 滤0分项
    if not useful: return handoff(low_confidence)              # 真正拒答条件=一条都没召回
    return generate(只按[引用N]回答, temperature=0.1)          # 引用约束生成
```

**追问点**：min_score 为什么这么低？→ 分数是 RRF 融合值（1/(60+rank)，量级0.01-0.03），不是余弦相似度；真正的拒答是"没有任何有效引用"。局限：对"召回了但不相关"拦不住，需相似度阈值/Reranker。

## 6. 受控 NL2SQL（目录召回+模板+参数契约）◆ 模型只填参数不拼SQL

```text
func analyze(query, user):
    if isSqlShaped(query): return unsafe_sql_shaped_input   # 入口只收自然语言
    template = 目录召回候选 + 校验 is_approved AND allowedRoles(user)  # 人工审核过的模板
    validateReadonly(template.sql)   # SELECT/WITH开头, 禁DDL/DML/分号/注释/长度≤20000
    params = bindParams(template.metadata.parameters):
        system_constant / system_now / natural_language(正则抽) / authorized_scope_only(subject授权闭包)
        校验: 数量≤12, 字符串≤256, limit 1..100, 日期≤366天
    # 目录引用范围：SQL引用的表/列 ⊆ 模板声明 ⊆ 活跃可查询目录(非敏感列)
    validateCatalogAllowlist(template.sql, catalogRecalls)
    sql = "SELECT * FROM (" + template.sql + ") AS t LIMIT :limit"   # 外层LIMIT兜底
    try: result = execute(text(sql), params=绑定参数)   # SQLAlchemy绑定参数，不拼字符串
    except: rollback; return execution_failed            # 防事务中毒
    return result + queryPlan(read_only=True, free_sql=False)
```

**追问点**：为什么不直接让模型生成 SQL？→ 无法保证只读/权限/防注入；模板可静态审查、口径统一、可审计。`nl2sql_ready=False` 明确关闭自由 SQL。

## 8. Outbox + Worker ◆ 业务与事件同事务，至少一次+幂等

```text
# 写业务
func createOrderAndNotify(...):
    with 事务:
        insert order
        insert outbox_event(notification.order_created, payload)   # 同事务commit
    # 业务成功 ⇒ 事件必落库，无分布式事务

# outbox worker
func publishOnce():
    events = SELECT * FROM outbox_event WHERE status=pending
             ORDER BY created_at LIMIT 20 FOR UPDATE SKIP_LOCKED   # 多实例安全
    for e in events:
        e.attempt += 1; commit                                    # 认领落库
        try: publish(redis_stream_by_type(e.type), e.payload)     # 按event_type路由
             mark_published(e)
        except: e.attempt>=max ? status=dead : status=pending     # 重试/死信

# 流 worker（消费者组）
while True:
    claim_pending(30s超时接管) + consume_once(XREADGROUP BLOCK 5000)
    处理(幂等：先查后插+唯一索引) ; ack
```

**追问点**：为什么不直接同步调？→ 慢调用拖垮主链路；Outbox 同事务保证不丢、Streams 持久化+重放、幂等键保证不乱。

func updateMemory(id, newValue, version):
    cur = read(id)                                # 读当前版本
    if cur.version != version:
